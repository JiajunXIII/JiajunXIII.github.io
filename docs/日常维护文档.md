以下流程用于“首次主页正式发布完成之后”的日常维护。普通文字修改、新增 News、新增论文都直接在 `main` 操作，不创建分支。

**一、同步线上版本**

打开 PowerShell：

```
cd "E:\JiajunX\PycharmProjects\JiajunXu.github.io-main\JiajunXu.github.io-main"

git switch main
git pull --ff-only origin main
git status
```

`git status` 应显示工作区干净，然后再修改内容。

**二、修改对应文件**

主要维护位置：

- 简介、研究方向、News、论文、科研经历、教育和荣誉：`_pages/about.md`
- 姓名、Email、GitHub、头像和 SEO 描述：`_config.yml`
- 顶部导航：`_data/navigation.yml`
- 头像和论文图片：`images/`

修改普通文字时，只改文字内容，尽量不要删除 `<section>`、`<div>` 等 HTML 结构。

页面底部更新时间也在 `_pages/about.md`：

```
<p class="last-updated">Last updated: August 2026</p>
```

**三、启动本地调试**

另开一个 PowerShell 窗口：

```
wsl -d Ubuntu-22.04
```

进入 WSL 后执行：

```
source /home/jiajunx/anaconda3/etc/profile.d/conda.sh
conda activate homepage-jekyll

cd /mnt/e/JiajunX/PycharmProjects/JiajunXu.github.io-main/JiajunXu.github.io-main

bash run_server.sh
```

看到 `Server running` 后访问：

http://127.0.0.1:4000/

也可以在 PowerShell 中打开：

```
Start-Process "http://127.0.0.1:4000/"
```

修改 `_pages/about.md` 后页面通常自动刷新。

修改 `_config.yml` 后必须：

1. 在运行 Jekyll 的窗口按 `Ctrl+C`。
2. 重新执行 `bash run_server.sh`。
3. 刷新浏览器。

**四、本地检查内容**

至少检查：

- Desktop 页面是否正常
- 浏览器缩窄到手机宽度后是否正常
- 图片是否加载且未裁切
- 姓名、标题和长句是否异常换行
- 新链接能否打开
- 导航能否跳到正确模块
- 页面是否存在重叠或横向滚动

遇到旧图片缓存时，按 `Ctrl+F5` 强制刷新。替换图片最好使用新文件名。

**五、执行正式构建**

停止本地 server，或另开一个 WSL 窗口，然后执行：

```
source /home/jiajunx/anaconda3/etc/profile.d/conda.sh
conda activate homepage-jekyll

cd /mnt/e/JiajunX/PycharmProjects/JiajunXu.github.io-main/JiajunXu.github.io-main

BUNDLE_FROZEN=true JEKYLL_ENV=production \
bundle _2.2.19_ exec jekyll build --trace
```

看到 `done` 且没有错误，说明正式构建成功。

不要执行 `bundle update`，不要修改 `Gemfile.lock`。

**六、提交前查看改动**

回到 PowerShell：

```
git status
git diff --check
git diff
```

确认只包含本次修改，没有手机号、微信、申请材料、本地绝对路径或敏感信息。

**七、提交并 push**

普通文字修改：

```
git add "_pages/about.md"
git commit -m "docs: update homepage content"
git push origin main
```

如果同时修改配置：

```
git add "_pages/about.md" "_config.yml"
git commit -m "docs: update homepage profile"
git push origin main
```

新增论文和图片：

```
git add "_pages/about.md" "images/new-paper-framework.jpg"
git commit -m "docs: add new publication"
git push origin main
```

尽量精确 `git add` 文件，不使用 `git add .`。

**八、检查线上更新**

Push 后 GitHub Pages 会自动重新构建网站，但不会自动爬取论文内容。

等待数分钟后访问：

https://jiajunxiii.github.io/

如果没有立即更新：

1. 查看仓库的 `Actions` 页面。
2. 查看 `Settings > Pages` 的部署状态。
3. 部署完成后按 `Ctrl+F5` 强制刷新。

**九、新增论文的具体方法**

1. 将论文框架图放入 `images/`。
2. 打开 `_pages/about.md`。
3. 在 `Publications` 中复制现有的整个 `<div class="paper-box">...</div>`。
4. 修改 venue badge、标题、作者、期刊/会议、日期和简介。
5. 修改 Paper、Project、Code 链接。
6. 没有 Project 或 Code 时，删除对应链接，不保留空链接。
7. 按上述本地预览、正式构建、commit、push 流程发布。

当前 Google Scholar workflow 已禁用，不会自动发现新论文。即使以后启用，也只建议更新引用统计；完整论文条目仍由你手动维护。
